## 2. 架构（第二阶段）

```
浏览器 SPA (frontend/，独立静态服务，端口 5500)
        │  HTTP/JSON（CORS）
FastAPI REST (/api/v1，端口 8000)
  ├─ POST /ask                单轮 GraphRAG 问答
  ├─ /sessions/*              多轮会话（指代改写 + 消息持久化）
  ├─ /graph/*                 图谱（节点搜索/邻居/子图/统计）
  ├─ /quiz/* /mastery         自测与掌握
  ├─ /search/compare          关键词 vs 向量 vs 混合(RRF)
  ├─ /versioning /health /stats
        │
服务层
  ├─ QAService         GraphRAG 编排：混合检索→图遍历→LLM/摘编→拒答
  ├─ ConversationService 会话 + 指代改写（LLM 优先，降级拼接）
  ├─ GraphService      节点/邻居/子图/统计
  ├─ QuizService       抽题/判题/错题/不重复
  ├─ MasteryService    掌握标记
  └─ VersionService    时效过滤 + SUPERSEDES
        │
检索层
  ├─ keyword (jieba + 评分)
  ├─ vector  (Embedding API / 本地哈希向量器)
  └─ hybrid  (RRF 融合 + 检索对比)
        │
存储层 (SQLite)
  documents/clauses/entities/relations/faq/quiz
  + vector_index / sessions / messages / mastery / quiz_attempts
```

**解耦与降级（§7.2）**：LLM、Embedding 均为可选外部依赖——未配置或失败时分别降级为"原文摘编"和"本地哈希向量器"，问答与检索链路不中断。

## 3. 关键设计

### 3.1 向量检索与降级

- 配置 `EMBEDDING_API_KEY` + `EMBEDDING_BASE_URL` 时走 OpenAI 兼容 `/embeddings`；
- 否则用 `HashingEmbedder`：字符 n-gram 哈希分桶 + L2 归一化，**确定性、离线、可复现**。
- 向量写入 `vector_index` 表，导入时幂等补齐（`ensure_vector_index`）。
- **运行期降级（对齐 §7.2）**：向量路抛异常（本地模型损坏、API 抖动等）时，`search_hybrid` 内部捕获并**降级为关键词单路检索**，问答不中断；降级原因经 `degradation_notice` 透出，用户提示"语义检索暂不可用，已切换关键词模式"。只有一路时 RRF 依然成立，无需分支处理。由 `tests/test_qa.py::test_at09_*` 锁定（AT-09）。
- **拒答判定以关键词检索为准**：本地哈希向量器对中文区分度有限，会把无关条款召回，因此"关键词零命中且无 FAQ"即判拒答，避免校车类问题被向量噪声误命中（AT-03 保持正确）。降级状态下该判定同样生效，不因降级而放开编造。

### 3.2 混合检索 RRF

`score(d) = Σ_r 1/(k + rank_r(d))`，k=60；关键词与向量命中按内容指纹去重后融合，返回 Top-K。`/search/compare` 同时暴露三路结果，便于"对比不同检索方式效果"。

### 3.3 多轮指代追问（AT-04）

- 检测到指代词（那/这/它/这个…）时：LLM 可用则依据历史改写为自包含问题（如"那补考呢"→"补考的规定是什么"）；否则启发式拼接上一轮问题。
- 会话与消息持久化到 `sessions` / `messages`，重启不丢（P1 已在 SQLite 持久化，优于"进程内记忆"的降级方案）。

### 3.4 时效过滤与 SUPERSEDES（AT-11）

- `active_documents`：仅保留 `status='现行有效'` 且 `effective_date <= today` 且**未被替代**的文档；
- `SUPERSEDES` 关系（新 doc → 旧 doc）导入时校验端点；检索只命中现行文档；
- 若证据含被替代文档，回答附加冲突提示。

### 3.5 自测与错题（AT-06）

- 抽题：`avoid_answered` 优先抽未答过的题（不重复出题）；题库不足时回填已答题；
- 判题：记录 `quiz_attempts`，返回正确项与解析；错题集取最近作答错误项，可整卷重做。

### 3.6 掌握标记（AT-07）

- `mastery` 表以 `item_id`（实体 eid 或 clause:{id}）为主键，状态 mastered/unmastered；
- 问答时若相关实体在"未掌握"集合，追加学习提示。

## 4. 工程规范

- **前后端分离**：`frontend/` 为纯静态 SPA（原生 JS，无构建依赖），后端只暴露 REST JSON；CORS 由 `CORS_ORIGINS` 控制；前端 API 基址可用 `?api=` 覆盖。
- **密钥安全**：LLM/Embedding 密钥只写 `.env`（`.gitignore` 已排除）；`config.py` 兼容 UTF-8/GBK 编码与 DeepSeek/OpenAI 两套变量名。
- **结构化日志**：`logging_util` 输出单行 JSON（request_id / session_id / elapsed_ms / mode / hits / degraded）。
- **统一错误**：`AppError` 体系 + FastAPI 异常处理器，返回 `{code, message, request_id}`；空问题/超长走 400，存储不可用 503，资源不存在 404。

## 6. 已知限制与第三阶段衔接

- 本地哈希向量器语义能力弱于真实 Embedding，正式环境建议配置 `EMBEDDING_API_KEY`（BGE/Qwen 等）。
- 图谱可视化采用自研轻量力导向 SVG（无 D3 依赖），大规模子图（>500 节点）性能有限，可在第三阶段引入 D3/Neo4j 浏览器。
- 会话持久化当前为 SQLite，第三阶段可迁移 Redis/PostgreSQL（§6 挑战版#15）。
- 第三阶段待办：答案引用全量可展开、检索评测（Recall@K）、增量入库、容器化。
