# 校园知识问答系统 · 第一阶段设计说明

> 依据《校园知识问答系统_项目设计文档.md》第 9 节「第一阶段：可运行、可验证（P0）」实施。
> 本文档补齐第一阶段要求的：需求拆解、架构图、数据模型、技术选型说明。

---

## 1. 需求拆解（第一阶段范围）

第一阶段只做**可运行、可验证的最小链路**，对齐设计文档 §6「基础版（P0，必须完成）」：

| 编号 | 需求 | 对应验收 |
| --- | --- | --- |
| F1 | 知识数据导入：PDF 解析 → 语义切分 → 元数据 → 入库，脚本幂等 | AT-01 |
| F2 | 实体检索：精确检索 + 关键词检索 | AT-02（部分） |
| F3 | 单轮问答：提问 → 检索 → 生成带引用答案；无结果明确拒答 | AT-02 / AT-03 |
| F4 | 基本界面：CLI + 最小 Web 页面 | — |
| F5 | 错误处理：空问题、超长（>2000 字）、数据库不可用 | AT-08 |

**第一阶段明确不做**（留待 P1/P2）：向量检索、图遍历（GraphRAG）、多轮会话、时效过滤、自测刷题、混合检索与 reranker、容器化。

### 1.1 需求 → 模块映射

| 需求 | 模块 | 说明 |
| --- | --- | --- |
| F1 解析 | `app/ingest/parser.py` | 按"第X章/第X条"语义切分，无结构则按段落 |
| F1 导入 | `app/ingest/importer.py` | PDF/txt → 文本 → 切块 → SQLite，稳定 ID + INSERT OR REPLACE 幂等 |
| F1 统计 | `app/ingest/stats.py` | 最小规模校验（§5.2） |
| F2 检索 | `app/retrieval/search.py` | 关键词/精确/FAQ 匹配 |
| F3 回答 | `app/service/qa.py` | FAQ 确定性回答 / LLM 生成 / 原文摘编降级 / 拒答 |
| F4 界面 | `app/cli.py`、`app/web/server.py` | CLI + FastAPI 页面 + Swagger |
| F5 错误 | `app/errors.py` | 统一错误码与中文提示 |

## 2. 架构图（第一阶段）

```
┌──────────────────────────────────────────────────────────────┐
│  交互层                                                       │
│  CLI (python -m app.cli ask/import/stats/serve)               │
│  最小 Web 页 (FastAPI + /docs Swagger)                        │
└───────────────────────────┬──────────────────────────────────┘
                            │ HTTP / 函数调用
┌───────────────────────────▼──────────────────────────────────┐
│  服务层 (app/service)                                         │
│  QAService.ask():                                            │
│    校验 → 检索 → FAQ命中? → 确定性回答                         │
│            → 无命中?  → 诚实拒答(AT-03)                       │
│            → 有命中?  → LLM生成(失败则原文摘编降级)             │
└───────────────┬──────────────────────────────┬───────────────┘
                │                              │
┌───────────────▼───────────────┐   ┌──────────▼──────────────┐
│  检索层 (app/retrieval)        │   │  LLM(可选, app/service)  │
│  关键词分词(jieba/兜底)        │   │  OpenAI兼容 Chat API      │
│  条款评分 / 实体 / FAQ         │   │  未配置即降级             │
└───────────────┬───────────────┘   └─────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────────┐
│  存储层 (app/db.py, SQLite)                                   │
│  categories / entities / documents / clauses / relations      │
│  faq / quiz / import_log                                      │
└──────────────────────────────────────────────────────────────┘
        ▲
        │ 导入 (app/ingest)
        └─ data/raw/*.pdf(手册) + manifest.json（元数据）
           data/kg/*.json（实体/关系） data/faq.json data/quiz.json
```

**组件解耦原则（对应 §4/§7.2）**：LLM 为可选外部依赖——未配置或调用失败时，问答自动降级为"原文摘编"，不影响检索与拒答；SQLite 不可用时统一抛 `StorageUnavailable` 并给中文提示。

## 3. 数据模型（SQLite 起步，第二阶段迁 Neo4j）

| 表 | 用途 | 关键字段 | 对应 §5.1 节点/关系 |
| --- | --- | --- | --- |
| categories | 主题分类 | name, description | Category |
| entities | 实体节点 | eid, kind(entity/department/process), name, category | Entity / Department / Process |
| documents | 源文件 | doc_id, title, issuer, publish_date, effective_date, status, version, applies_to, content_hash | Document |
| clauses | 条款/段落块 | doc_id, chapter, article_no, content, seq | Clause |
| relations | 关系 | src, rel, dst, note（主键 src+rel+dst 保证幂等） | CONTAINS/ISSUED_BY/HANDLED_BY/REQUIRES/DEPENDS_ON/AFFECTS/SUPERSEDES… |
| faq | 问答对 | qid, question, answer, category, source | Question/Answer |
| quiz | 自测题 | qid, category, difficulty, question, options(JSON), answer, explanation | Question（题库） |

**稳定 ID 约定**：实体 `dept:*` / `proc:*` / `ent:*`，文档 `doc:*`，FAQ `faq:*`，题库 `quiz:*`。关系端点引用这些 ID，导入时做**引用完整性校验**（悬空即报错）。

## 4. 技术选型说明

| 层 | 选型 | 理由（第一阶段取舍） |
| --- | --- | --- |
| 语言/框架 | Python 3.10+ / FastAPI + Uvicorn | 与设计文档一致；自动生成 Swagger，便于验收与演示 |
| 图存储 | **SQLite** | §5.3 明确"基础版可用 SQLite 起步，标准版迁移 Neo4j"；第一阶段无图遍历需求，SQLite 零外部依赖、可复现 |
| 检索 | 关键词/精确匹配（jieba 分词 + 评分，兜底正则） | 第一阶段不做向量（P1）；jieba 未安装时自动降级为规则切分 |
| LLM | OpenAI 兼容 Chat API（智谱/DeepSeek/Qwen/Ollama） | 可选、默认关闭；关闭时降级"原文摘编"，保证离线可演示 |
| 文档解析 | pypdf | 手册为 PDF；文本型 PDF 直接抽取，扫描件 OCR 属后续阶段 |
| 测试 | pytest + httpx(TestClient) | 覆盖 AT-01/02/03/08 |

**为什么第一阶段不直接用 Neo4j / 向量库**：可复现性优先（AT-10：新电脑按 README 即可跑）。数据模型已按"节点/关系"抽象，第二阶段可近乎无痛迁移到 Neo4j + 向量索引。

## 6. 已知限制与第二阶段衔接

- 手册 PDF 若为扫描件（无文本层），导入会给出占位提示，OCR 属后续阶段。
- 实体/关系/FAQ/题库当前为**示例数据**（人工整理，符合 §1.3"人工校验"），正式上线需据《2025 版学生手册》原文逐条校验。
- 第二阶段将加入：向量检索、Neo4j 图遍历、多轮会话、时效过滤、自测与错题、健康检查完善与日志结构化。
